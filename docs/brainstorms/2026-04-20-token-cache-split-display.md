## Fundamentals

**Claude API token taxonomy:**
- `input_tokens` — non-cached portion of the prompt (new tokens sent cold)
- `cache_creation_input_tokens` — tokens newly written to prompt cache (5-minute TTL)
- `cache_read_input_tokens` — tokens served from cache (not re-sent, but consumed context)
- `output_tokens` — tokens generated by the model

**Why this causes extreme skew:** Claude Code sends the system prompt + tools (often 50-200K tokens) on every turn. With cache, the first turn writes it (cache_creation), all subsequent turns read it (cache_read). A 20-turn session may have `input_tokens`=100K total but `cache_read_input_tokens`=4M. Showing only `input_tokens` as "Tokens In" makes the session look 40× smaller than reality.

**What the user wants:** Two things, separately:
1. Fix the wrong number in `cost-aggregator.ts` (the last unfixed accounting bug)
2. Show cached and non-cached tokens as distinct values in every display

## Root Cause Map

### Bug 1 — cost-aggregator.ts:47 (WRONG NUMBER)
```typescript
// WRONG:
const inTok = usage.input_tokens || 0;
// CORRECT:
const inTok = (usage.input_tokens || 0)
  + (usage.cache_read_input_tokens || 0)
  + (usage.cache_creation_input_tokens || 0);
```
**Impact:** `CostSummary.tokenIn24h` / `tokenIn7d` feeds `commandFormatters.ts` `/analytics` command and `PromptInput.tsx` footer. Numbers undercount by up to 100×.

### Bug 2 — CostSummary type missing cache fields
`CostSummary` has `tokenIn24h/7d` but no `cacheRead24h/7d` or `cacheWrite24h/7d`. Even if we fix the aggregation, cache breakdown can't be surfaced.

### Display Issue 1 — CostStrip.tsx

Fix: Show `In: 5K raw · 200K cached` or `In: 5K (+200K cached)`.

`tIn = metrics?.tokens.inputTokens` — same problem, feeds session header.

### Display Issue 3 — AgentNodeCard.tsx hover tooltip
