Coaching analysis Follow-up work is being split across new sessions
What happened
Across the last 7 days, you opened 9 separate sessions against claude-devtools that all picked up the same task thread — fixing the subagent state machine. Each session started with the same 4 file reads (dag-builder.ts, agentStatus.ts, metrics.ts, the matching test file) before any productive work began.
Why it matters
Reloading those 4 files costs ~8.4K input tokens per restart, plus ~30 seconds of agent orient time. Across 9 sessions that's ~76K tokens and roughly 4 minutes spent on context re-acquisition — the equivalent of a full small refactor turn that produced nothing.
Recommendations
  1. When you switch to follow-up work on the same repo, resume the prior session instead of /clear or new session.
  2. Use /compact at the top of a long thread to preserve context cheaply rather than dropping it.
  3. If a task is genuinely new, copy the relevant CLAUDE.md excerpt into the first prompt so the model skips the orient reads.
